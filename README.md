# 🏎️ DetailingHub — Production Automotive Detailing Operating System

> Современная полнофункциональная операционная веб-система для премиальных студий автодетейлинга, кузовного ремонта и стационарного/выездного ухода за автомобилями. Построена на стеке **Next.js 15 (App Router)**, **React 19**, **Prisma ORM**, **TypeScript** и **Tailwind CSS**.

Архитектура спроектирована на основе проверенных решений индустриальных систем управления автосервисом (**ARK Core**, **Nexcal**, **Cal.com**, **Dealership Loaner Platform**).

## 🛡️ Архитектурные принципы и закрытые крайние случаи (Edge Cases)

### 1. Жизненный цикл заказа и строгий State Machine
* **Защита от срыва работ (Cancellation Window):**
  * Клиент может отменить запись через сайт **только не позднее 3 часов** до заезда.
  * Если до заезда осталось `< 3 часов` — кнопка отмены блокируется с выводом предупреждения: *«Мастер и бокс уже подготовлены. Пожалуйста, позвоните администратору»*.
* **Автомобиль в работе (`in_progress` / `ready` / `completed`):**
  * Как только мастер принимает автомобиль и переводит статус в `in_progress`, клиентская отмена **блокируется наглухо** (в API строгий Guard с ответом `403 Forbidden`).
* **Атомарное освобождение ресурсов (Atomic Bay Release):**
  * При отмене заказа в единой транзакции Prisma освобождается связанный бокс (`Workbay`) и бронь (`Booking`). Временной слот в `/api/slots` сразу становится доступен другим клиентам.
* **Аудит отмены (Audit Trail):**
  * Фиксируются `cancelledAt` (дата/время), `cancelledBy` (`client` | `admin`) и `cancelReason` (причина).

### 2. Официальный Заказ-наряд А4 (Печать и векторный PDF)
* Встроенный `@media print` шаблон в `/order/[token]` формирует строгий бело-чёрный бланк формата А4 по стандартам автосервиса:
  * Реквизиты студии («DetailingHub», адрес, телефон, сайт);
  * Данные заказчика и ТС (марка/модель, госномер, VIN, класс, пробег при сдаче);
  * Таблица заказанных услуг и материалов с ценами и статусом расчетов;
  * Дефектовочная ведомость кузова (список сколов и повреждений ДО начала работ);
  * Гарантийные обязательства (14 дней без щелочной мойки после нанесения керамики);
  * Места для подписей: «Автомобиль сдал» (Клиент) и «Автомобиль принял» (Мастер).
* **0 сторонних npm-пакетов** — векторное сохранение в PDF средствами браузера.

### 3. Почасовая детализация постов (Workbay Timeline) в `/admin/booking`
* Месячный календарь с возможностью выбора любого дня;
* Мгновенный срез загрузки студии: состояние каждого бокса (*Мокрый*, *Сухой*, *Сушка*);
* Список назначенных автомобилей со временем заезда, телефоном клиента и ссылкой на бланк А4;
* Отменённые брони отображаются с причиной отмены и пометкой *«Бокс свободен»*.

## 🎨 Дизайн: Apple Design Philosophy
* **Монохромность (Restraint):** строгий титановый/белый логотип `#F5F5F7` на глубоком обсидиановом фоне `#0A0A0C`. Никаких пёстрых разноцветных логотипов.
* **Обсидиановый Glassmorphism:** матовые стеклянные панели `bg-zinc-950/70 border border-white/[0.08] backdrop-blur-xl`.
* **Плавное сглаживание:** векторные силуэты автомобилей отрисованы на плавных SVG-кривых с аппаратным ускорением (`transform-gpu`, `antialiased`).
* **Отказ от дешевых баннеров:** убраны кричащие эмодзи и блестки, акцент на эстетике премиального ухода за автомобилем.

## 🚀 Быстрый запуск проекта

### 1. Клонирование и установка зависимостей
```bash
git clone <URL_РЕПОЗИТОРИЯ>
cd car-detailing-studio
npm install
```

### 2. Настройка базы данных и начальных данных (Seed)
```bash
npx prisma db push
node scripts/seed.mjs
```

### 3. Запуск тестов
```bash
node scripts/test-e2e.mjs
```
*(Проверяет базу данных, расчет P&L, DVI акт осмотра, смену статусов и аудит отмены — 8 этапов на 100%).*

### 4. Запуск в режиме разработки
```bash
npm run dev
```

* **Клиентский сайт:** [http://localhost:3000](http://localhost:3000)
* **Панель управления:** [http://localhost:3000/admin](http://localhost:3000/admin)
* **Логин по умолчанию:** пароль `admin12345` (меняется в `/admin/security`)

## 📦 Сборка и деплой в Production

```bash
npm run build
npm start
```

* Для деплоя на VPS (Ubuntu / Docker / PM2) проект использует устойчивую SQLite-базу `prisma/dev.db` и локальное хранилище фото `uploads/`.
* Для бессерверного деплоя (Netlify / Vercel) достаточно переключить `datasource db` в `prisma/schema.prisma` на PostgreSQL (Neon / Supabase), подробнее в [README-NETLIFY.md](README-NETLIFY.md).
